Digital Twin architectures describe recurring responsibilities such as data
ingestion, processing, storage, Twin state, and visualization, but they do not
by themselves establish which cloud services form a complete implementation or
whether a cost-selected multi-cloud assignment can be deployed reproducibly.
This thesis presents Twin2MultiCloud, a research proof of concept that connects
a typed workload, functional provider resolution, cost calculation,
Infrastructure as Code deployment, runtime verification, and cleanup across
Amazon Web Services, Microsoft Azure, and Google Cloud Platform.

The system operationalizes one versioned Six-layer architecture in which
Eventing and Messaging is an explicit responsibility. Candidate assignments
are ranked by monthly cost only after their components, cross-cloud edges,
identity requirements, deployment artifacts, verification steps, and cleanup
contracts have been resolved. Frozen, source-attributed pricing snapshots and a
digest-linked evidence chain make the calculation and deployment decision
reproducible. The implementation intentionally remains a single-user PoC: it
uses one local owner profile, encrypted cloud connections, immutable Twin
deployments, explicit confirmation for cost-incurring operations, and bounded
user-function extensions, while omitting production authentication,
multi-tenancy, generic architecture plugins, and in-place infrastructure
updates.

The evaluation separates deterministic offline validation from supervised live
cloud execution. It defines three provider-local baselines and six directed
AWS/Azure/GCP multi-cloud scenarios for one Small workload, with numerical
budget caps, immediate functional probes, mandatory Destroy attempts, and
post-Destroy inventory checks. The resulting method is designed to assess how
provider-specific service bundles can implement one shared architecture and
whether layer-wise provider selection changes estimated cost without treating
nominally similar services as automatically equivalent.
