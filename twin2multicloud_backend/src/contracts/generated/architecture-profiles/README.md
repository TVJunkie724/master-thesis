# Architecture Profile Contracts

This directory is the repository source of truth for the closed-world Phase 8
architecture model. Version 1 separates four records:

- `ArchitectureProfile`: provider-neutral logical responsibilities, components,
  edges, the exact optimization slots and functional-completeness rules,
  workload coupling, and graph policy;
- `ProviderImplementationProfile`: one provider's reviewed capability and
  mapping claims for one profile version;
- `DeploymentComponentCatalog`: explicit package, runtime, Terraform binding,
  port, permission, pricing, and cleanup metadata;
- `ResolvedTwinArchitecture`: one immutable, complete Optimizer resolution that
  references a `ResolvedDeploymentSpecification` instead of duplicating its
  deployment dimensions.

The semantic registry, schemas, fixtures, and shared runtime are the Phase 8.2
contract boundary. Phase 8.3 added generated, versioned production definitions
below `definitions/`: the baseline profiles, AWS/Azure/GCP implementation
profiles, deployment component catalogs, pinned source digests, and
completeness scenarios. Phase 8.9 activated the reviewed
`five-layer-baseline@2` and `six-layer-eventing@1` definitions across the
Optimizer, Management API, Deployer, and Flutter for offline calculation and
preflight. Historical `five-layer-baseline@1` remains read-only. Actual cloud
deployment stays fail-closed while a resolved supervised live gate is open.

## Source And Generated Copies

Edit schemas and validation behavior only in
`contracts/architecture-profiles/v1/`. Production definitions are generated
from reviewed repository evidence by
`scripts/architecture_profile_catalog.py`. Generated byte-identical copies live
below the Optimizer, Management API, and Deployer contract roots. Refresh and
validate them with:

```bash
python scripts/sync_architecture_profile_contracts.py --generate-fixtures --sync
python scripts/sync_architecture_profile_contracts.py --check
python scripts/check_architecture_profile_catalog.py
```

Use a project/container Python environment containing the locked `jsonschema`
dependency. Generated directories and `.contract-sha256` markers must never be
edited by hand.

The Phase 8.3 completeness gate parses HCL with `python-hcl2`, re-hashes
allowlisted package source without following symlinks, verifies pinned package
builders and Python handler modules/callables, and checks Terraform
variables/outputs, deployment dimensions, `thesis-demo-v1` capabilities,
pricing intents, formula IDs, edge behavior, the exact seven Phase 8.1
optimization slots and twelve functional-completeness rules, and the
`processor.telemetry@1` provider adapters. It performs no cloud call.

## Security And Versioning

Validation is local-only: remote schema fetching is unsupported. Documents are
size/depth/count bounded, fail closed on unknown versions, reject secret-like
keys and credential-shaped values, and expose stable `ARCH_*` error codes
without echoing payloads. Content digests cover canonical content except the
digest field and audit timestamps. Existing resolutions never upgrade
implicitly.

`ResolvedDeploymentSpecification v1` remains unchanged and valid only for
`five-layer-baseline@1`. Both active profiles use RTA v2/RDS v2 and Manifest
v4; Six-layer adds its Eventing component and edges without modifying the
closed v1 enum or the inherited Five-layer v2 L1-L5 contract.
